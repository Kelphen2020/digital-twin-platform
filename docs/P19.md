# P19.0 部署与扩展

## 1. 本地生产模式栈

```bash
docker compose -f deploy/docker-compose.yml up -d --build
# PostgreSQL :5432 / API :8080 / Web(nginx) :8081
```

主 API 使用 PostgreSQL（迁移自动应用）、jsonl 事件总线（卷 `api-data`）。

## 2. 多副本 API（共享 PostgreSQL）

事件写入、用户、会话、巡检等状态都在 PostgreSQL，副本之间共享；唯一「粘性」的是**本次事件由哪个副本接收**。为避免非主副本收到未知相机的检测：

- 环境变量 `INGEST_FALLBACK_URL`：非主副本把 ingest 原样转发到主副本，并把上游响应（含状态码）回传。
- 转发的请求带 `INGEST_FALLBACK_URL` 目标 `/api/ingest/detections`，保留 `X-Ingest-Token`。
- 指标：`dsh_twin_ingest_forwarded_total`、`dsh_twin_ingest_fallback_failures_total`；不可达返回 `502 fallback_unavailable`。
- 示例：

```bash
# 主副本
docker run -d --name dtp-api-1 -p 8080:8080 \
  -e DATABASE_URL=postgres://twin:twin@pg:5432/twin?sslmode=disable \
  digital-twin-platform/api:latest
# 第二副本（8082），ingest 回落到主副本
docker run -d --name dtp-api-2 -p 8082:8080 \
  -e DATABASE_URL=postgres://twin:twin@pg:5432/twin?sslmode=disable \
  -e INGEST_FALLBACK_URL=http://dtp-api-1:8080 \
  digital-twin-platform/api:latest
```

> WebSocket 推送不做跨副本广播：需要推送一致性的场景请在 nginx 配置 WS 粘性（`ip_hash`），或后续接入 Redis Pub/Sub / Kafka 总线。

## 3. Web 反向代理

`deploy/nginx.conf`（HTTP）与 `deploy/nginx-tls.conf`（HTTPS+HSTS）已包含静态站点、`/api`、`/ws` 升级、`/hls` 静态；多副本时可把 `proxy_pass` 指向 upstream 组。

## 4. 验证

```bash
# 单副本 compose
curl -s http://127.0.0.1:8080/api/health
# 多副本 ingest 回落
curl -s -X POST http://127.0.0.1:8082/api/ingest/detections -H 'Content-Type: application/json' \
  -d '{"camera_code":"CAM-001","detections":[{"class":"intrusion","confidence":0.9}]}'
# 指标
curl -s http://127.0.0.1:8082/metrics | grep ingest_forwarded
# 单元测试
cd services/api && go test ./internal/api/ -run Ingest -v
```
